What moves over

        
Everything you actually notice
when you switch browsers.

        
Not a half-migration that leaves you resetting 40 passwords. Every piece is written in Chrome's own encrypted format, so Chrome treats it as its own.

      


      

        

          

          
Cookies & sessions

          
Read over the DevTools protocol, then written directly into Chrome's cookie store with host binding and the real v10 encryption. You stay logged in.

        

        

          

          
Saved passwords

          
Extracted through Comet's own autofill on the original origin, encrypted immediately, then verified by filling them again in a profile copy.

        

        

          

          
History

          
Visits merged by timestamp and URL, so nothing duplicates. Your Chrome history keeps what it had and gains what Comet knew.

        

        

          

          
Downloads

          
The list in chrome://downloads comes along, file paths included. No re-downloading anything you already have.

        

        

          

          
Autofill & search

          
Form entries, addresses' inputs and custom search engines. Typing two letters in the address bar feels like home again.

        

        

          

          
Backups first

          
Every touched database is copied to %LOCALAPPDATA%\comet-chrome-migrate\backup before a single byte is written.

Safety

          
Yours stays yours.

          
Browser data is the most sensitive thing on a desktop. This tool reads it, encrypts it and puts it down again — it never asks for an account, a server or a clipboard.

          
No network calls except closing and opening your browsers. No telemetry. Read the source; it is about 1,500 lines.

        

        

          
No plaintext, ever
Passwords live in memory for milliseconds and land encrypted. Not a CSV, not a JSON, not a temp file.

          
Chrome's real key
Writes use the DPAPI key from Chrome's Local State, so Chrome reads the data as its own — no injection tricks.

          
Comet is not modified
Its profile is only copied. If something looks off, the run aborts and the backup goes back in place.

          
Roundtrip check
After importing, one cookie and one password are decrypted again and compared. A silent failure would be worse than an error.

FAQ

        
The obvious questions.

      

      

        

          Why does Comet not just do this itself?
          
Chromium can import from Chrome, Edge, Firefox and a few others — the direction out was never implemented. Comet inherits that. Exporting means reaching into the profile directly, which is what this tool does.

        

        

          Does it work with Chrome already signed in?
          
Yes. Existing Chrome data stays; migrated entries are merged. Sync may later push the new history and passwords to your other devices, which is usually what you want.

        

        

          Will it ask for Windows Hello?
          
No. Chrome's re-authentication-before-filling is a separate setting that is off by default, and the tool never opens the password manager UI. It also never touches the fingerprint or PIN prompt.

        

        

          What about bookmarks and extensions?
          
Not migrated. Comet ships with no bookmark export and its extensions are Chromium web-store extensions you would reinstall anyway. History, sessions and passwords are the parts that hurt to lose.

        

        

          Which profiles are supported?
          
The Default profile of both browsers. Multi-profile setups are not detected, and the tool says so instead of guessing wrong.

        

        

          Is this allowed?
          
It is your machine and your data. Nothing is bypassed that protects someone else; the encryption keys are yours, stored by Windows for your user account. Unofficial tool, use at your own risk, MIT licensed.
